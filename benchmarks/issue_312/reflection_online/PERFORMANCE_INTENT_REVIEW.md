# Performance and intent review

No unresolved implementation blocker was found in the tested CPU path. Online adaptation remains experimentally defined, not proved stationary; no performance observation removes that statistical limitation. The post-run correlation fix is restricted to diagnostic reporting.

- Measured: all 180 runs used one CPU per numeric process; peak core RSS was 2.769 GiB and peak analysis RSS 0.843 GiB. Four pilot slots expanded to 24 only after measured checks. No GPU was used. Actual final storage is recorded in RAW_INVENTORY.json.
- Measured: final depth compile caches have size 2 for capacities 9,750/19,500 and size 3 when capacity also reached 39,000. Online histories changed parameters 6–18 times, while cache counts followed buffer shapes. The fixed-shape value-change test passed. This does not prove every future configuration avoids retracing.
- Compiler-observed: at capacity 19,500 and width 150, contour preparation uses 313,366 argument bytes, 3,624 output bytes and 1,564,264 temporary bytes. Dispatch uses 5,865 argument bytes, 11,662 output bytes and 13,824 temporary bytes. These are executable plans for the controller seams, not whole-process peaks. The preparation compilation timing is a cache hit after obtaining prepared inputs; it is not a cold compilation benchmark. Exact HLO and source are preserved with COMPILER_INSPECTION.json.
- Measured: online median contour preparation costs 5.62 s (uniform) and 6.34 s (evidence), host update costs 0.069/0.100 s, and feedback transfer costs 0.261/0.369 s. Full-process logged compilation includes setup outside the core timer; do not subtract it from core wall time. SUMMARY.json retains all per-run costs and variability. Full replay and evidence reduction are charged separately, never used as free controller feedback.
- Inferred scaling risk: preparation builds capacity-sized classic block/volume data every batch. Feedback transfers width-sized jump/work arrays; it does not copy the entire sample capacity to the host. The immutable policy has float64 shape [65,2], support [2] and scalar version as dynamic Pytree leaves. Frozen policies use fixed actual-likelihood knot arrays and never access evaluation compression for their choices.
- Inferred execution risk: heterogeneous midpoint counts execute in a vectorized batch whose longest lane can dominate hardware work. Logical gradient/value counts are correct and fully audited, but they are not an exact CPU-work model. No production steady-state speedup is claimed from these short compiled runs.
- Precision and intent: actual cube/parameter arithmetic remains float64 with the original TFP model-scale precision. No tolerance, kernel, posterior weighting, seed source or allocation law changed. Controller history is explicit Python-owned state; the checkpoint also retains pending statistics, versions and ledgers. Existing scientific kernels and evidence reduction are reused.
- Diagnosed and fixed after numerical completion: a repeated three-value seed column has a tiny roundoff-positive SD while its squared column has zero SD. Strict JSON correctly rejected the undefined correlation. The reusable helper now checks exact range separately for coordinates and squared coordinates, and returns null for any nonfinite correlation. Four regression cases cover the two exact recorded values, normal/underflow behavior, and strict JSON records. The temporary generic serializer wrapper is archived only as the exact executed repair, not installed as a reusable interface.

All 45 final combined tests passed with one existing TFP deprecation warning. Ruff, Flake8 (100-character limit) and git diff checks cover the touched benchmark/test source. There is no production src/jaxns or manuscript diff. No asynchronous-dispatch runtime claim, GPU claim, numerical precision reduction, or new performance optimization is included.
